# D3 — durable crashed-work preservation

`internal/recovery/preserve` implements the production `recovery.PreservationPort`. It captures a complete tree against the immutable base using `gitio.BuildCandidateTree`, transfers exact blobs and modes into the origin object database, and publishes the deterministic recovery ref create-only. A matching ref or archive is adopted after a publication/record crash. If the ref cannot be published, a private `safefs` archive stores a checksummed manifest and exact paths, modes, symlink targets, and bytes. Changed later work receives a distinct archive identity; an earlier candidate is never replaced.

If workspace Git cannot produce a candidate tree, the archive fallback captures the workspace's non-`.git` files, including ignored files, so recoverable bytes remain available while Git is unavailable. Unsupported special files or failed publication return an error; the recovery controller then retains the workspace and candidate refs with `cleanup_pending` for terminal retry. Every preservation record remains `unverified` and cannot grant landing permission.
