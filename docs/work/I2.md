# I2 Provider/account boundary

## Component

`internal/app/provider_routes.go` implements provider list, use, login and logout over the existing descriptor-rooted account store and file credential vault. ChatGPT login and logout use the PKCE/JWKS OAuth client; Grok login and logout use the device-code client. The route only writes machine state under `HOME/.kogen`.

The focused app test drives discovery, authorization, callback, PKCE exchange, RS256 identity verification, persistence, account selection, listing, revocation and logout through a local fake OIDC server. It verifies the saved credential has mode `0600` and that listing an empty home does not create account state. No live account is accessed.

`cmd/kogen-xspec/protocol.go` composes the existing production-backed intent, approval, queue and status factories behind the strict xspec/1 protocol transport. The transport's malformed, unknown-operation, unknown-slice and unknown-event refusals remain in `internal/xspec/protocol` and its tests.

## Wiring boundary

The provider method is not dispatched from `CLI.runCommand`: `internal/app/foundation.go` remains the I1 route switch and returns its provider integration placeholder. That file was outside I2's owned paths, so the public command route remains an integration closure gate. Likewise, `cmd/kogen-xspec/main.go` still calls `app.Bootstrap`; the new factory composition helper is compiled but is not yet the executable's entrypoint. The exact v1.2 run is recorded in the evidence note and does not convert those unwired routes into passes.
