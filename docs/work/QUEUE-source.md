# Go work queue

This is a future dispatch plan, not a running build. Read [PLAN.md](PLAN.md) first. Create neither `kogen-go` nor worker worktrees during this planning job.

## Dispatch and acceptance contract

One package = one **gpt-6-luna / max** worker, one isolated worktree, one owned file set, at most the stated **60–90 minutes**. Times include focused tests and a commit. At the cap, stop at a reviewable boundary and split the remainder into another bounded package; retain the existing branch and evidence. Do not silently expand a worker into a multi-hour subsystem task.

Packages are listed in preferred order. A dispatcher may start later independent rows once their dependencies are **merged** with their required component or behaviour gate accepted. Start three workers; serialize integrations, fake OAuth port 1455, process-custody stress tests and race suites. Workers commit but do not merge, push, install or change another worktree. Required interface changes go to the coordinator and are merged before dependent dispatch. Do not edit the spec, suite, goldens or replay harness to get green. Target **v1.3-draft `e19dd1c`**, including its three blockers and four should-fixes, from day one.

Each file set below includes tests within that directory and a unique `docs/work/<ID>.md` evidence note. `/**` means that subtree exclusively; non-recursive `*.go` means only that directory. No package may claim a parent subtree containing another owner's subtree. Package 00 creates shared contract files and entrypoint shells; subsequent entrypoint/composition changes belong only to the serialized integration owner. A package may create a new file in its owned subtree, never append to a shared registry, Makefile, go.mod or central work log. The coordinator owns queue/progress records and central contract amendments.

Every worker reads its current spec clauses, `CHANGES-v1.3.md`, normative data and relevant Rust modules. Put production decisions in reusable transitions/effect interpreters; xspec packages decode/inject/map only. Tests use isolated HOME/Git and fake endpoints. `make check` must pass offline. Record implementation/CLI/adapter SHA, exact resolved IDs and instance counts, replay scenarios/seeds/divergence and unresolved issues. All **compatible** conformance anchors must be green at their closure round; draft-conflicting anchors must be run and reported with their exact incompatible assertion, then their shared frozen next-suite replacements must turn green. No old demotion or destructive cleanup path is implemented just to pass v1.2. A foundation may merge component-green as code-ready before wiring, but is not behaviour-accepted until its closure round.

### Case notation and commands

Use `C=cli`, `S=state`, `A=approval`, `H=shape`, `B=build`, `L=ladder`, `P=provider`, `U=custody`, `F=format`. `A03` is `approval-03`; `A01–07` expands seven IDs. `V03` means the exact case whose ID starts `v1.2-03-`; `V104` starts `v1.2-104-`. These are aliases for frozen IDs, not new tests. Spec `P1`–`P13` means requirements in `CONFORMANCE-v1.2-CASES.md`, distinct from provider aliases `P01` etc. `R(slice)` means all frozen hand scenarios plus **500×25** generated traces for each seed **17, 23, 41**, with full observations. D(slice) is diagnostic, never a release pass.

Always pass the **entire standard profile selection plus v1.2 overlay**, then filter by case IDs. The runner automatically substitutes superseded old IDs via `profiles/v1.2.json`:

```sh
bin/kogen-conformance run --kogen /absolute/bin/kogen \
  --profile cli,state,approval,shape,build,ladder,provider,custody,format,v1.2 \
  --case 'approval-03,state-08,v1.2-03-*' \
  --jobs 2 --time-scale 0.02 --workdir /absolute/evidence/WP/work \
  --out /absolute/evidence/WP/results.jsonl
```

Resolve aliases/ranges to a literal case list and fail selection if zero cases match. Final historical runs omit `--case`: **236 cases /570 expanded instances**, including five login-marked cases. Shared next-suite v1.3 gates have their own frozen denominator. Local planned draft fixture names below are specifications for that suite, not assertions that case files already exist. Each anchor can be shared; the final ledger names an accountable integration owner and contributors. Historical L05–11/V73–79 and wider demotion/ranking/report cases need replacement; audit/recovery/schema/cache conflicts are inventoried rather than falsely counted passing.
