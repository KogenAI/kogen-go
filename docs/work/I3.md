# I3: First executable approval to landing

`queue start` and `queue stop` now dispatch to the queue drain. The start route resolves the project, creates the private recovery and preservation controllers, derives approved queue entries from status and approval refs, then runs the one-rung Build controller. Its verification path materializes the immutable base, runs the real gate and configured command acceptance adapter, creates the candidate commit, and publishes through the landing compare-and-swap. The status command then observes the landed approval.

`internal/app/build_routes_test.go` exercises the public `CLI.Run` sequence with an injected fake plan/build agent and a real temporary Git origin. It asserts one planner call, one builder call, a green acceptance receipt, one-parent landed commit, and landed status. The invalid-approval test asserts the queue stops before either fake model call.

The production route fails closed when no Build agent is configured (`provider/build_agent_unavailable`). The fake is an app test seam; a production ChatGPT plan/build adapter is a later closure. The route currently accepts the `command` acceptance adapter. ExUnit and Rails adapters remain unwired here. A moved-base landing can be gated and safely parked, but automatic repair/base refresh is not configured.

The recovery adapter ignores only empty approval-preparation run directories with no `run.json`; all other recovery issues stop the drain. Run-owned child cleanup after parent death relies on the process guardian. After a successful landing, the route removes the already-preserved workspace using `os.Root`, because the single-rung terminal cleanup path rejects `.git` as a controller-data path. The controller's subsequent cleanup observes the missing workspace.
